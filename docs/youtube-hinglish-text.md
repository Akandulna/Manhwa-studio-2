# Hinglish text inside the existing YouTube workspace

There is no additional Hinglish page or tab. The Titles tab displays a second card for the selected title, derived exactly as the English title plus ` - Hindi`, with its own copy button. Editing the selected English title updates the derived card. Existing titles are never silently shortened. New title prompts target 92 characters to leave room for the eight-character suffix; existing overlength derived titles show an editing notice.

The Description tab displays English and Hinglish cards in one two-column desktop row (stacked on narrow screens). The English card is English prose. The Hinglish card is an alternative wording for the Hindi recap: it opens with a 2–3 line hook in Roman-script Hinglish, continues in English prose, and must naturally contain `in Hindi`. One ChatGPT prompt generates both descriptions, retaining the same verified story facts while changing sentence structure, hook and closing. Copy and edit controls work independently, and editing either card retains the other text.

New description requests use an internal outputVersion=2 marker. Their JSON output retains the existing schemaVersion=1, requestId, seriesId, language=en and exact base English title, and adds hinglishDescription alongside description. Both fields are validated before either is saved. Each is limited to 5,000 Unicode characters. The Hinglish text must include the case-insensitive phrase “in Hindi” and cannot be identical to the English description with only that phrase/punctuation added. Exact repeated imports compare both fields; changed replays are rejected.

Existing English-only requests and saved descriptions remain available. Missing Hinglish text appears as an empty card rather than generated/fabricated content. Preparing a new prompt does not reuse an older single-description request. Older requests can still be resumed/imported from history; the UI offers an explicit new paired prompt. Importing a legacy English-only response preserves existing Hinglish text and marks it for review if necessary.

Workspace additions are optional hinglishDescription and hinglishDescriptionNeedsUpdate fields. Paired immutable versions snapshot both texts and their review flags. Restoring a paired version restores both; restoring a legacy English-only version preserves existing Hinglish text with a review flag. Title changes preserve both texts and flag each for review. Review of one language variant never clears the other variant’s warning. Existing revision conflicts, JSON presentation recovery and series/title/request identity checks are retained.

The library reports Hinglish Not started, Title ready, Needs update, or Title & description ready. English readiness and manual completion remain independent. Hinglish thumbnails are deferred: no image prompts, image imports, reference clipboard behavior or thumbnail selection semantics change here.

Validation: 76 focused tests (72 server workflow/storage/HTTP/parser tests and four rendered-component checks), server/client TypeScript and the production web bundle. Coverage includes paired import atomicity, duplicate wording, the required Hindi mention, legacy requests, editing either variant, history restoration, stale reviews, derived-title preservation and two-column card rendering. Tests use temporary workspaces; no user descriptions are generated or overwritten by these checks.
