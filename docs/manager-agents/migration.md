# Migration, compatibility, privacy, and rollout design

## Proposed persistence (not installed)

Relay: additive versioned tables `manager_schema`, `entity_mappings`, `manager_events`, `manager_observations`, `managed_tasks`, `managed_attempts`, `managed_commands`, `managed_artifacts`, `managed_reservations`, `manager_incidents`, `manager_incident_events`, `manager_notifications`, `manager_accounts`, `manager_ui_changes`. Unique workspace/event ID, task identity tuple, task/generation, command/attempt, cause/resource active incident, consumer/notification ID, and reservation resource constraints are required. The claim transaction checks enrollment/current revision, writes attempt+command intent+all reservations together, or writes nothing. Incident impacts/history are child records or append events, not overwritten text. Acknowledgment is a separate nullable timestamp, independent of resolved status. Recurrence reopens the cause/resource incident and increments its occurrence generation; exact event replay never creates a new alert.

Desktop: proposed local projection/identity/outbox tables in Prisma, separate from current production Setting records. Phone: proposed SQLite attempt/command/checkpoint/outbox journal. Persist event + local checkpoint in one local commit where possible; relay accepts idempotently before deleting outbound event. Retry after disconnect retains original source time/event ID. Acknowledgment lost after durable acceptance causes replay, not another action. Do not store full screenshots or account secrets in SQL/receipts. Artifact staging keys contain opaque workspace/task/attempt/artifact IDs, never account names. Canonical references are committed only by current-owner conditional publication.

## Mapping and rehearsal

1. Disable proposed managed switches. Stop new legacy dispatch and reconcile existing active work before enrollment.
2. Back up desktop SQLite with a consistent database backup (including WAL state via SQLite backup API), download roots/checkpoints, relay exports, identity mappings and phone journals. Never copy only a live .db file. Record checksums and manifest versions. Production backups remain private.
3. Restore only into a temporary isolated workspace and a local Wrangler persistence directory, with separate test bucket binding and fake phone IDs. Reject production relay URLs/tokens/bucket names in test harness configuration. No integration test may default to environment production credentials.
4. Apply additive schema migrations transactionally and twice to verify repeat safety. Preserve original UUIDs, owner settings, legacy receipt payloads and timestamps. Map imports through origin IDs; unresolved folder/name collisions stay unmapped. Do not rewrite ownership to the importing Mac.
5. Import validated existing outputs as artifact evidence only after current input hash and destination validation. Receipts without provenance become last-known/unknown. Existing running/interrupted commands remain uncertain; production job IDs do not become proof of task ownership. Manual completion/archive remains an explicit override.
6. Crash/restart during each migration/outbox/publication boundary; compare counts, checksums, mappings and preserved history. Re-run restore using a fresh isolated directory and demonstrate readback before enabling production migrations. These are Phase 8 rehearsal steps, not checks completed in Phase 0.

## Proposed feature switches / capability handshake

All defaults false: `managerObservations`, `managerIssues`, `managerUiMonitor`, `managedCropPage`, `managedMultiDevice`, `accountAudits`, `automaticRecovery`, `aiDiagnosis`. Scope by workspace/device/workflow; require prerequisites from the delivery plan. The observation/Issues rollout must not change legacy scheduling. Disabling a view does not purge durable events/incidents. Disabling dispatch/recovery stops new actions and retains pending stops/uncertain attempts.

Handshake advertises `manager-observations/1`, `managed-task/1`, `attempt-fencing/1`, `reconnect/1`, `command-journal/1`, and `artifact-publication/1` separately. A legacy device may report last-known receipts, but cannot join managed execution. Version mismatches return explicit unsupported-protocol with required capability; never downgrade a managed start to a legacy request. Deploy compatible relay first, then desktop and released phone builds. No APK is built/installed locally.

Rollback: stop new claims → preserve/reconcile active attempts and stop intent → disable affected switches → use only a protocol-compatible application. Keep schema/history/outboxes and immutable artifacts. Never restore an old database over newer active ownership, and never free uncertain profile capacity just because a lease expired.

## Evidence and supported website states

Shared evidence is allowlisted: opaque object/reference, checksum, capture time, redaction status, expiry. Strip cookies, tokens, authorization headers, query secrets, passwords, email addresses, payment details, conversation text not needed for diagnosis, and source content from shared logs. Screenshots are off by default; enable only with a specific capture policy. Redact locally before upload; unredactable captures stay local and are not attached. Proposed retention: redacted screenshots 7 days, redacted diagnostic structures 30 days, metadata/event history 90 days; delete expired objects and their accessible previews while retaining a minimal redacted audit marker. Respect explicit deletion and record failed purge for retry. Retention defaults are design choices requiring validation before evidence capture is enabled.

Initial Phase 2 baseline scope is ChatGPT clipping composer/attachments/response actions, Gemini Web clipping composer/attachments/response actions, AI Studio clipping prompt/uploads/model settings/response actions. Also classify loading/streaming, sign-in, quota and upload-error overlays as transient or blockers, not redesigns. Baselines must identify page/workflow, locale, viewport, theme, profile/account variant, required semantic controls, ignored dynamic content, capture/hash and adapter version. There are **no validated live baselines yet**. First comparable observation is baseline-missing, not confirmed change; unsupported/unvisited variants remain unchecked. Confirmed cosmetic changes notify through the same chain as blocking changes. Daily idle audit defaults to 24h (optional 48h) and defers while active.

## Initial execution/fallback policy

No new provider/profile/model policy is owner-approved by this task. Phase 0 authorizes design/fixtures only. Existing ProductionConfig choices remain the explicit choices for existing runs. Proposed managed pilot requires the owner to select a concrete device/profile/provider/model/settings before enrollment; blank settings must be resolved and shown. Default new fallback policy is `wait`, allowed alternative list empty; no provider rotation, quality downgrade, quota estimate use, new audit navigation or paid capacity test is enabled. Owner pause/cancel and review gates persist across restarts.

## Baseline measurements and open release gates

Record connected event latency, event bytes, relay operations, idle/active phone CPU/battery, checkpoint durability, and real background renewal delays using local synthetic workloads, then a compatible device. No measurement is claimed in Phase 0. Simulation timings in decisions.md cannot authorize production expiry/reassignment. Missing Android fixture execution, live baselines, measured budgets, and actual backup rehearsal remain explicit gates; none blocks writing the Phase 1 observation adapters.
