# Protocol decision record: manager-agents/1

Status: implementation baseline for Phase 0, 18 October 2026. These decisions do not enable runtime control.

## Authority and identity

Use the existing relay Durable Object's SQLite store as one workspace authority for tasks, attempts, commands, reservations, incidents, identity mappings, and accepted observations. Keep coordinated claims in one transaction/DO; no R2 lock or Mac process lock is authoritative. Mac ProductionRunner proposes new work. Closing the Mac stops new scheduling in the initial release. Workers retain submitted results for reconciliation; no automatic phone-only failover is promised.

The authenticated connection determines workspace and source permissions; never trust a body-provided device, role, or workspace alone. The authority allocates UUID shared series/chapter/page IDs and persists mappings from `(workspaceId, originDeviceId, localEntityId, entityKind)` to shared IDs. Preserve library origin ownership. Existing manifests identify series by owner/folder and chapters by number/name, not stable shared chapter IDs; desktop replica chapter UUIDs can differ. Reconcile an origin's legacy manifest with local rows once, record the explicit mapping, and refuse ambiguous collisions until reviewed. Titles, paths, chapter numbers, and file hashes are discovery hints, not identity. Rename updates aliases; byte-identical pages can still be distinct entities. Reinstall without the original identity cannot silently replace an origin.

Task identity is the exact tuple `(workspace, series, chapter, stage, language-or-null, unit.kind, unit.id, inputFingerprint)`, encoded as a JSON array before SHA-256, prefixed `task:sha256:`. Do not concatenate delimiter-separated strings. Run IDs only group tasks. The fingerprint is SHA-256 of a versioned canonical JSON execution specification: ordered dependency shared IDs/revisions/content hashes, prompt and validator versions, provider/product/model/settings, language, and output-affecting policy. Sort object keys recursively, retain array order, use UTF-8, disallow nonfinite numbers and undefined. Resolve device defaults to explicit values before assignment. A compatible profile move requires proven context portability and unchanged specification; output-affecting changes create a new fingerprint/task and supersede the old attempt.

## Wire contract

`protocol/records.schema.json` defines strict version 1 records for identity, observation, task, attempt, command, artifact, reservation, incident, account, and UI change. Every envelope carries immutable event ID, workspace, authenticated source identity, durable monotonic source sequence, original observedAt, receiver-stamped receivedAt, and redacted evidence references. Retry sends the same event ID, sequence, payload, and observedAt. Replaying must not update freshness. Source sequence is a safe JSON integer persisted across restarts; sequence reset requires a new registered source ID and reconciliation, never wall-clock last-write-wins. Deduplicate by `(workspace, eventId)` and reject conflicting reuse of an event ID. Order facts within `(source, entity, fact kind)`; do not let another source's sequence replace it. Stale revisions are retained as historical evidence but cannot satisfy current work. Future timestamps beyond tolerance are quarantined; source clock skew is displayed, not repaired by a dashboard refresh.

The fixture receivedAt is the authoritative receiver time for accepted-record examples; producer ingestion omits it and the authority supplies it. Unknown schema versions fail closed for control and are retained as unsupported diagnostics for observation. Unknown additional fields require a negotiated schema change. Commands require task, attempt ID, attempt generation, command ID, input fingerprint, and action. Idempotency is per command/attempt; a sent socket frame never proves acceptance. Persist command intent and worker accepted intent before each corresponding side effect.

Observation facts keep work state, revision compatibility, review, and per-destination availability separate. Phone validation owns phone generation evidence; R2 HEAD/checksum/version evidence owns cloud availability; the Mac importer and module validator own imported/validated Mac evidence. No source may assert another destination's validation. The legacy max-progress projection remains visible separately while adapters report disagreements. Manual part marks/archive completion remain explicit overrides, never managed task completion evidence.

## Transitions and external action boundaries

The executable cases in `protocol/transitions.json` are normative safety examples; `verify.mjs` is a specification oracle only, never imported by production.

| Action | Durable intent before action | Acknowledgment / checkpoint | Unknown outcome handling |
|---|---|---|---|
| Claim device/profile/task | Authority transaction creates attempt generation and all reservations | Committed assignment | Retry same claim ID; read current owner before any action |
| Dispatch / accept start | Authority command outbox; worker local accepted-command journal | Correlated accepted, then started | Assigned → uncertain on disconnect; no alternate dispatch without reconciliation |
| Navigate / select profile / model | Step intent, expected page/profile, current ownership | Postcondition from correct page/profile | Inspect restored state; never reload a pending generation |
| Upload attachment to provider | Attempt-scoped upload intent and content hash | Visible attachment identity/readiness, not chooser close | Inspect attachment/rejection; hold unknown upload allowance consumption |
| Submit prompt or correction | Pending submission journal with prompt hash, conversation reference, step and command | Observed provider submission/response association | Set uncertain even if click callback failed; no timeout-based replay |
| Save response/checkpoint | Raw response staged locally with input/task/step fingerprint | Validated reply and atomic checkpoint write before next step | Re-read and validate saved checkpoint; never regenerate accepted units |
| Export page / upload cloud artifact | Attempt-specific staging manifest and immutable hashes | Local validator; then cloud object/version/checksum | Partial export/upload is not completion; inspect staging and reuse valid output |
| Publish canonical metadata | Authority compares current attempt generation, revision, review, and evidence in transaction | Verified complete and released reservations | Old attempt/revision rejected; retain staged artifacts for reconciliation |
| Import / process / render | Destination operation ID, dependencies and expected files | Destination validator and file hashes | Retry only missing transfer/import/processing, never phone generation |
| Pause / stop / finish current | Authority pause/cancel flag plus stop command intent | stop-requested then correlated stop-confirmed or reconciled stopped | Remain stop-pending, retain resource uncertainty; no automatic resume |
| Audit / UI observation | Idle-session reservation if navigation needed | Timestamped scoped facts or deferred/unknown | No prompt/upload; busy audit waits, failed check does not imply logout |

Lease expiry changes ownership confidence to uncertain, not permission to claim again. Only reconciled confirmed-unsent or confirmed-released attempts with no unresolved submission can return to queued. Saved output is not verified complete until current-ownership publication and module validation. Cancelled/superseded attempts never resume. Revision changes preserve old evidence and invalidate only dependent work. Stop and review gates take precedence over recovery. Acknowledging an incident only records acknowledgment; resolution requires new validating evidence. UI notification acknowledgment never accepts a baseline.

Proposed timing test configuration: lease 120 seconds, renew every 30 seconds, progress deadline specific to stage (initial crop-page diagnostic threshold 10 minutes). These are simulation values, not Android-validated production defaults. Stalled progress opens an incident; it never establishes safe resubmission. Tune from foreground/background tests before Phase 3 enrollment.

## Pilot: one crop page

Select `crop_json`, language null, unit `page`, one stable shared page ID at a fixed page/prompt/config fingerprint. Start with one explicitly chosen provider/profile and one lane; multi-tab and profile rotation wait for authority reservations.

Inspected Android `autorun/ClipperRun.kt`: `nextPage` rechecks `PageSections` DONE state; the claimed-page set and `lane.sent` are in memory. `runClassic` pastes responses through `ClipperPage.paste`; `runSteps` loads/pastes persisted steps. `runPage` calls `ClipperPage.export` before incrementing progress. `clipper/ClipperPage.kt::export` requires a ready validated review, checks round-trip geometry and JSON crop counts, writes `.incoming`, replaces the destination, then writes EXPORT_REPORT_FILE before scheduling ChapterUpload/ClipperReceipt/PhoneShare. The report stores source SHA, review revision, output names, count, provenance. `PageSections.status` checks output compatibility. This provides a concrete page-sized recoverable artifact, but the destination replacement and report are not one crash-atomic transaction. A crash between them requires file/report reconciliation. Existing export can delete the old destination; managed mode must use immutable attempt staging instead.

Required Phase 3 changes: persist pending prompt/upload before website action; bind saved page/step checkpoints to attempt and specification; compare ownership at every action and canonical publication; integrate manual exports/imports with enrollment protection; retain ambiguous conversations. Neither local claimed sets nor existing auto-resume is shared ownership. Do not select a sub-page prompt as the initial cross-device unit: provider conversation context and in-flight request state are not durably portable today.

ChatGPT execution is in `autorun/ChatGpt.kt`, `ChatGptControls.kt`, `ChatGptOptions.kt` and ClipperRun's PageDriver; other adapters are `AiStudio.kt`, `GeminiWeb.kt`, `GeminiSettingsDom.kt`. Phase 2 must record baseline fixtures from supported comparable states, not infer live compatibility from these filenames.
