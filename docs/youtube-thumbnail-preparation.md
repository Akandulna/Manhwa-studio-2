# Thumbnail automation — reference preparation stage

The thumbnail-generation popup adds Prepare references with Sleeper Cell for each selected variation. Choose a compatible phone and prepare the draft. This stage pastes the existing variation prompt, attaches 1–10 selected crop snapshots and, for edits, base-thumbnail.png. It confirms the upload count and deliberately stops before Send. It does not generate, download, import or select an output image. Existing manual prompts, reference clipboard, downloadable packs, thumbnail imports and Hindi overlay remain available.

The existing youtube_start command carries a youtube-automation/1 job with kind=thumbnail_prepare and slot=0..2. Studio snapshots the prompt and references from the saved thumbnail request. Immutable PNGs are uploaded first to <phone-prefix>youtube/attachments/<job UUID>/<fixed filename>. The package records each key, filename, byte length and SHA-256. Per-image transfers are limited to 20 MB and the complete pack to 100 MB. Crop references remain limited to ten; the optional base image is additional. Current title, revision, slot and capability are checked before dispatch. Jobs deduplicate per saved request and variation; unresolved jobs reserve their phone.

Phone capability automation.youtube.thumbnailPreparation=youtube-thumbnail-prepare/1 is required; older betas retain title/description support. No relay deployment or protocol permissions change is needed. The phone verifies job/device/expiry, fixed attachment paths, unique filenames, sizes and hashes. Downloads are bounded to declared byte length and streamed to the existing FileProvider exports cache. Only the owning run's WebView can consume the pending chooser payload; other WebViews and nonimage choosers are ignored. ChatGPT + / Photos uses the existing trusted PageDriver taps. All expected image tiles must show uploaded and ready for two consecutive checks. Upload limits, missing controls, partial uploads, cancellation and image corruption fail preparation.

The phone stores a prepared acknowledgment before uploading it, preserving recovery through the existing same-job replay. It includes the exact job/request/series/device/kind, variation slot and attachment count. No submission marker is written and Send is never tapped in this branch. Studio marks the job ready only after matching the envelope, variation and full count; it also rechecks the selected title. Preparation does not alter the workspace or create an output thumbnail. The prepared draft remains in its phone tab for inspection.

Validation includes seven new Studio transport/storage tests covering exact bytes and hashes, upload-before-command order, base images for edits, capability and slot checks, deduplication, unchanged workspace state, incomplete acknowledgments and failed transfers. Existing YouTube and managed-admission regressions, client build and server TypeScript are checked. Android contract tests cover fixed paths, identifiers, size bounds and hashes. Phone attachment preparation is a separate live validation from the previously passed title/description flow. Full image generation and return are the next implementation stage.
