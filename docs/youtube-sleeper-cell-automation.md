# Sleeper Cell automation for YouTube text

The existing title and description generation popups offer a connected phone selector and Generate with Sleeper Cell. Manual Copy prompt / Paste response remains available beneath it. Titles return five validated suggestions without selecting one. After the user chooses a title, a separate description run returns the paired English and Hinglish descriptions from the existing prompt and JSON contract. Thumbnail automation is outside this change.

The bridge sends an immutable `youtube-automation/1` package to the chosen phone's configured R2 prefix under `youtube/jobs/<UUID>.json`, then delivers the targeted `youtube_start` relay command using the UUID as its series field. Packages include the exact prepared prompt, request, series, kind, target device and 30-minute expiry. The phone accepts only UUID job keys, checks identity and expiry, and runs ChatGPT in a fresh tab on its currently selected profile. It accepts a verified text paste or ChatGPT's long-paste attachment. Existing managed enrollment restrictions, remote-start setting, beta Off mode, shared browser run ownership, pause/resume and stop behavior remain enforced. YouTube has its own run-bar label and ChatGPT lane.

The phone records submission before tapping Send. A repeated job reuploads its saved result, or reports an uncertain prior submission; it never automatically sends the same prompt again. Completed replies are saved locally before upload to `youtube/results/<UUID>.json`. Errors and cancellations return an explicit error envelope where possible. A failed upload retains the completed response. No profile switching, quota retry or provider fallback occurs automatically in this first version.

Studio persists dispatch state and checks results at most once per 15 seconds, including while the popup is closed. Monitoring resumes after server restart until expiry. Result identity must match the exact series, prompt, operation, device and job. The existing parser and workspace revision validation handle import. Changed workspaces or invalid output retain the raw response for manual recovery rather than overwriting saved content. The service deduplicates repeated clicks and reserves a phone while an unexpired request has an unresolved outcome. Manual title selection remains a user action.

Readiness requires a connected phone advertising the protocol, remote start enabled, an idle phone, and the relay's `youtube-automation/1` feature. Older phones and relays show an update requirement. The protocol and prefix are advertised in the crops receipt's automation.youtube field. Existing phone run-kind parsing remains unchanged; YouTube capability is checked explicitly.

Server API additions: GET /api/youtube/automation/phones; GET /series/:seriesId/automation/:kind/latest?requestId=...; POST /series/:seriesId/automation/:kind/start; POST /series/:seriesId/automation/jobs/:jobId/check. Job metadata is stored under server/.config/youtube-automation, separate from workspace history.

Validation: 103 focused Studio tests (including 11 automation transport/storage/HTTP/recovery tests), client web build, server and relay TypeScript, Android testDebugUnitTest and testBetaUnitTest offline, and the existing ChatGPT model-chip script fixtures. A real ChatGPT generation has not been run as part of these checks.
